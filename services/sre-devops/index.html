SRE / DevOps

監視・アラート・インシデント対応まで、システムの安定稼働を継続的に支援します。

こんな課題に向いています

  • 障害が起きてから利用者の連絡で気づく、という状態が続いている
  • アラートが多すぎて、重要なものが埋もれている
  • 特定の担当者しか対応できない領域があり、休暇も取りにくい

対応範囲

  • SLO / SLI の設計と、運用ダッシュボードの構築
  • アラート設計とノイズ削減（何をもって「起こすか」の再定義）
  • インシデントレスポンス体制の整備と、ポストモーテムの運用
  • パフォーマンスチューニングとキャパシティプランニング
  • 障害復旧・DR策の策定と、実際の切り替え訓練

考え方

アラートは、緊急度を厳密に設計します。 影響範囲と対応の緊急性から重大度（Critical / Warning / Info など）を定義し、重大度ごとに通知先と対応期限を分けます。鳴っても何もしないアラートが混ざると、本当に対応が必要な通知への反応が鈍ります。既存のアラートを棚卸しし、対応手順が書けないものは削除するか、ダッシュボード表示に降格させます。

お客様が期待するサービスレベルに寄り添って設計します。 性能・可用性を上げようとすれば、コストは増えます。まず業務にとって本当に必要な性能や稼働率をお客様とすり合わせ、その上でコストや技術的な制約を踏まえた最適な構成を一緒に探りながら導入します。
